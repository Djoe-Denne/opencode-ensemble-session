# Mission-configured QA profiles

Keep profiles focused on durable expertise and permissions. The mission's
`verification` contract selects QA depth, agreed commands and acceptance criteria.
Present it interactively with `/ensemble-mission config`; `start` approves the
displayed policy. Use the plugin's current level definitions, not copied numeric
risk thresholds or a second independent QA matrix.

Suggested short profile instruction:

> Apply the mission's verification contract. Do not impose a planner/generator/
> reviewer pipeline because those profiles exist. If no contract was supplied,
> ask the lead to clarify consequential choices, proposing proportionate QA.
> Preserve project safety and accepted contractual requirements; report conflicts
> rather than silently waiving them. Separate blocking regressions from advisory
> findings and out-of-scope gaps. Reuse valid evidence. Propose any increase of
> scope or test infrastructure before executing it.

Light normally needs targeted author checks; proportionate adds checks/review
for concrete affected risks; reinforced calls for an explicit verification plan
and independent review. None requires deploying unrelated infrastructure or
spawning a fixed number of agents. Independent review can be one bounded mission.
An agreed failed check must be reported accurately, not hidden by choosing a level.

Adapt existing orchestrator/QA bodies in place. Replace conflicting fixed-pipeline
clauses, not just prepend this reminder above them. Preserve names, native modes,
models, tools and permissions; permission fixes require their own approved diff.
Keep immutable business/testing contracts outside these optional role recipes.

Verify: light local fix does not spawn a QA factory; reinforced authorization
change still honors real-integration requirements; an unavailable check becomes
an explicit limitation/arbitration, not a fabricated PASS or an unapproved harness.
